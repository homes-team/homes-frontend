# homes-frontend
프론트엔드

sign_up/agent랑 sign_up/commonuser를 합한 코드로 딱 하나 바뀐 부분: 에러 메시지 상태 분리

기존엔 페이지 하나에 errorMessage라는 상태 변수 하나를 계정정보 단계(이메일/비밀번호 에러)와 마지막 제출 단계(회원가입 API 실패, 서류 제출 실패) 둘 다 돌려썼습니다. 리팩터링하면서 계정정보 단계의 에러는 훅 안(accountStep.errorMessage)으로 들어갔고, 남은 단계의 에러는 페이지마다 새 이름으로 분리했습니다.

SignupWizardPage: 약관동의 단계 제출 실패 → termsError (새 변수)
SignupAgentWizardPage: 서류 제출 단계 실패 → documentsError (새 변수)

이게 왜 생겼냐면, 계정정보 단계 로직이 훅으로 빠져나가면서 그 안의 errorMessage를 다른 단계에서 가져다 쓰는 게 어색해졌기 때문입니다. 다만 화면에 보이는 동작은 완전히 동일합니다 — 원래도 단계를 넘어갈 때마다 setErrorMessage(null)로 초기화하고 있어서, 한 화면에 한 단계의 에러만 뜨는 건 리팩터링 전후 똑같습니다. 그냥 "변수 하나를 돌려쓰던 것"에서 "단계별로 각자 변수를 갖는 것"으로 내부 구조만 더 명확해진 정도입니다.

정리하면: 동작(API, 검증, 문구, 화면)은 하나도 안 바뀌었고, 에러 상태를 어느 변수에 담느냐만 더 깔끔하게 나뉜 것이라고 보시면 됩니다. 실제로 테스트해보셔도 이전과 똑같이 동작할 겁니다.
