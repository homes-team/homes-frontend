# 채팅방 나가기 후 처리 (백엔드 요청)

프론트는 채팅방에 들어올 때 `GET /chats` 목록과 대조해서 "내가 나간 방"과 "상대가 나간 방"을 막도록 처리했다
(내가 나간 방은 목록에서 빠지므로 목록에 없으면 막고, 상대가 나간 방은 `isUserLeft`/`isAgentLeft`로 판단).
다만 화면에서만 막는 것이라, 서버에서도 같은 규칙을 지켜줘야 완전히 막힌다.

## 요청 1. 나간 방에는 메시지를 보낼 수 없게 하기
- `ChatService.sendMessage`가 `room.isUserLeft()` / `room.isAgentLeft()`를 확인하지 않아서,
  한쪽이 나간 방에도 웹소켓으로 메시지가 저장되고 알림이 간다.
- 보내는 사람이 나갔거나 상대가 나간 방이면 거절해 달라 (예: `CHAT400_4 "나간 채팅방이에요."`).

## 요청 2. 나간 사람에게 채팅 알림을 보내지 않기
- 현재는 내가 나간 뒤에도 상대가 메시지를 보내면 `NotificationType.CHAT` 알림이 생성되고,
  그 알림으로 들어가면 다시 대화할 수 있었다. 나간 사람에게는 알림을 만들지 않아야 한다.

## 요청 3. (선택) 상대가 나갈 때 실시간으로 알려주기
- 상대가 나가는 순간 방에 있는 사람에게는 알릴 방법이 없어서, 다시 들어오거나 새로고침해야 "상대가 나갔습니다."가 보인다.
- `/topic/chats/{chatId}`로 "상대가 나갔어요" 이벤트(또는 시스템 메시지)를 한 번 보내주면 즉시 반영할 수 있다.

## 참고
- 매칭 확정 등으로 `createOrReopenRoom`이 호출되면 `reopen()`이 두 플래그를 모두 false로 되돌린다.
  이 경우만 나간 방이 다시 열리는 것으로 알고 있는데, 의도한 동작인지 확인 부탁드린다.
